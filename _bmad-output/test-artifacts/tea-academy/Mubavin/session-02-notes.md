## Key Concepts Covered

### 1. Testing as Engineering
- Tests are designed before they're written
- Tests have quality standards, not just "does it run?"
- Tests are maintained like production code
- Testing decisions are risk-based

### 2. Risk-Based Testing: P0-P3 Matrix
- **P0 — Critical:** Login, payment, data loss, security → Business fails if broken
- **P1 — High:** Core workflows, data integrity → Major user pain
- **P2 — Medium:** Secondary features, edge cases → Inconvenience
- **P3 — Low:** Tooltips, help text, aesthetics → Minimal impact
- Formula: Risk = Probability × Impact

### 3. TEA Definition of Done
1. No Flaky Tests — deterministic pass/fail
2. No Hard Waits/Sleeps — use waitFor conditions
3. Stateless & Parallelizable — no shared state between tests
4. No Order Dependency — every test works in isolation
5. Self-Cleaning Tests — delete/deactivate created entities
6. Tests Live Near Source Code — co-locate with code they validate
7. Low Maintenance — stable selectors, API setup, no repeated UI actions

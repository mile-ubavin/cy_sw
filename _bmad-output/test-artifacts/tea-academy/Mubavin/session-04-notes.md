## Key Concepts Covered

### 1. Test Design Workflow
- Plan tests BEFORE writing them (design before code)
- Steps: Load Context → Risk Assessment → Coverage Planning → Test Design Document
- Use for: new features, major refactors, quality gates before development
- Project example: DH_EG_03_Employees_TS_Create_EBox_User_Manually.js should have been preceded by a Test Design phase

### 2. Risk & Testability Assessment
- Risk = Probability × Impact (multiply, never add)
- High × High = P0 (critical, must test everything)
- Low × Low = P3 (low priority, manual or skip)
- Project examples:
  - Create EBox User: High probability × High impact = P0
  - Mass Upload: High × High = P0
  - Self Registration: Medium × High = P1
  - Tooltip text: Low × Low = P3
- Testability: assess dependencies and infrastructure needs before estimating effort

### 3. Coverage Planning
- Unit Tests: isolated functions, no external deps, fast
- Integration Tests: multiple components, DB/API interactions
- E2E Tests: full user workflow in browser (Cypress covers this layer)
- Strategy: P0 → Unit + Integration + E2E; P1 → Integration + E2E; P2 → E2E or Integration; P3 → Manual

### 4. Test Priorities Matrix
- Coverage targets: 100% P0, 80% P1, 50% P2, 20% P3
- Goal is proportional investment of test effort based on business risk
